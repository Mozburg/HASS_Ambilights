# Audit — 2026-11-11

Five read-only auditors over disjoint slices of the app, each reporting file:line claims
with evidence. Every finding below was re-checked here before anything changed; the
"fixed" ones were reproduced first, the "open" ones are recorded so the next session does
not have to rediscover them.

## Fixed in 2.8.0

| # | where | what | evidence |
|---|---|---|---|
| 1 | `post_config` | `{"persist": true}` reset **every** setting, light map included: one loop variable held both flags | POST with `persist: true` returned the defaults as `applied` and wiped `LIGHT_MAP` |
| 2 | `_coerce` | `int` settings rounded floats (2.6 → monitor 3); `string` settings accepted `null`/numbers/lists (`HA_URL: null` → `""`) | measured both through `/api/config` |
| 3 | `apply_settings` | a failed `config.json` write was reported as `persisted: true` | `/proc/…/config.json` returned 200 while the file never appeared |
| 4 | `apply_settings` | `_translate_legacy_colour` existed since 2.7.0 but **nothing called it**, so `COLOR_ALGO=mean` never reached `COLOUR_BLEND` — the documented migration was dead code | `apply_settings({'COLOR_ALGO':'mean'})` left the blend at 0.5 |
| 5 | `apply_settings` | two overlapping saves could lose one setting's write (no lock) | auditors reproduced with a widened write window; now one `RLock` covers apply+persist |
| 6 | capture loop | frames were stamped as attempted **before** the `TUNING` gate, so every frame during an auto tune suppressed its colour for `RESEND_AFTER` | code path; gate moved before stamping |
| 7 | sender | on success it stored `last_sent = last_attempted` (a re-read of shared state), so a frame queued mid-POST was marked delivered | snapshot of the posted tuple is taken before dispatch |
| 8 | sender | a refused/BUSY frame aliased `last_attempted = last_sent`, which made `should_send` treat it as confirmed and never retry | now cleared to `None`, which `should_send` retries at once |
| 9 | sender | the radio-stall branch bumped `target.busy` but not `stats["busy"]` | counters now agree |
| 10 | `restore_light` | an unguarded `_post` inside a `finally` could strand every remaining light on the test colours | one failed restore now logs and continues |
| 11 | startup | `threading.Timer(31, …)` was non-daemon, so an early-return start kept the process alive 31 s | measured: 33 s to exit |
| 12 | startup | `--server` with another instance running exited **0**, so systemd reported a clean start while nothing was served | now exits 3 with a log line |
| 13 | logging | `basicConfig()` ran at import, before the `--windowed` stream redirect, so every record wrote a 9-line "Logging error" traceback | handlers are re-pointed after the redirect |
| 14 | tests | the suite never set `CONFIG_FILE`, so running it rewrote the developer's own `config.json` | sandbox temp paths are set before import |
| 15 | `/health` | capture and sender now stamp heartbeats; `pipeline_ok` is false when either is stale | a dead thread used to answer 200 forever |

## Fixed in 2.9.0 (colour path, second pass)

- The brightness blend now reaches the sender — 2.7.1 computed `dominant_luminance` and
  then dropped it, because the substitution sat inside the `"dominant"` branch that the
  mean-colour case never enters. 126 → 191 on the auditor's frame.
- The 3×3 panel previews the substituted colour (ΔE 36 → 0 against the light chip), and
  chips keep their hue instead of clipping (orange `#ffc03a` → `#e87f23`).
- RGB mode no longer sends pink where xy sends red; a black frame no longer commands white.
- Colour stage 6.25 ms → ~1.6 ms per frame (one aggregate instead of 2 + N; the zone panel
  is only built while `/regions` is being polled).

`_in_srgb_gamut` was re-tested independently: 0 of 20 000 random in-gamut colours are
rejected, so the original claim stays dismissed. Two latent nits are recorded: it returns
True for `y <= 1e-6` (unreachable, both callers also check `valid_xy`), and the `-1e-4`
tolerance calls the blue primary out of gamut by 0.0006 (harmless — boosting a primary is a
no-op).

## Open — wave three

Ranked by damage, all reproduced by an auditor unless marked otherwise.

1. **4xx responses feed the host circuit breaker**, so one invalid entity id opens a 10 s
   global pause that repeats forever. Fix: breaker only for connection errors and 5xx.
5. **Neither thread loop restarts after an exception** (`sender_loop` catches once and
   returns; `capture_loop`'s prologue is unguarded). Heartbeats now surface it, but the
   loops should recover.
6. **`post_concurrently` creates a thread — and therefore a `requests.Session` — per
   request**, so keep-alive never happens on the concurrent path.
7. **`grid_from_shot` copies ~8 MB per frame** (`ascontiguousarray`), 3.8 of 7.8 ms;
   preallocating one buffer would remove it.
8. **`aggregate(lin)` runs twice per frame** for the full region (0.6–0.8 ms), and
   `preview_colour` twice per light.
9. **The UI re-persists the hidden legacy keys** on every save, because it posts all of
   `CFG` rather than the visible metadata.
10. **`reload()` calls `setDirty(..., true)`**, which fires a live POST on every page
    load, re-serialising `LIGHT_MAP` and dropping the file's formatting.
11. **`calibrate()`'s poll never stops** if `/health` fails, leaving the button disabled
    for the life of the page.
12. **`serializeMap` turns an empty zone set into `all`** — "clear every zone" saves as
    "drive the whole screen".
13. **Restart guard is time-only**: a legitimate second restart inside 30 s is refused
    with "fix the last change by hand".
14. **`BIND_HOST` is not checked for bindability**, so an unbindable address is saved and
    the restart then dies. IPv6 literals are also not bracketed in URLs.
15. **`build.ps1` never checks `$LASTEXITCODE`**, so it prints "Built dist\…exe" after a
    failed build (Windows PowerShell 5.1 ignores `$ErrorActionPreference` for native
    commands).
16. **The service unit's `Environment=BIND_HOST` is inert** once `config.json` has a value
    (verified), and the unit has no `User=`/`DISPLAY` despite needing the session display.
17. **Tests are a linear script of top-level asserts** — no runner collects them, the
    first failure skips everything after it, and it cannot run on Windows CI. Ranked
    missing tests: startup orchestration and exit codes, logging/rotation, legacy
    migration, `first_free_port` exhaustion, and every `os.name == "nt"` branch.
